Background
As a Cloud Engineer, one of the primary challenges is designing and building a cloud
infrastructure capable of handling automated, scalable, and secure image processing.
The system must be able to receive image files from various sources—such as mobile
applications, IoT devices, internal enterprise systems, or third-party APIs—and manage
a complex processing pipeline. This pipeline includes tasks such as validating image
format and size, pre-processing operations like resizing or noise reduction, and
performing intelligent analysis through AI-powered algorithms like object detection,
facial recognition, or content classification.
To build an efficient and reliable solution, a modern architecture that leverages managed
AWS services is essential. Amazon S3 serves as the core storage service, offering high
durability, scalability, and seamless integration with other AWS services. When images
are uploaded to S3, automated processing can be triggered using event-driven
mechanisms to invoke AWS Lambda functions. These serverless functions are ideal for
lightweight operations such as validation or metadata extraction, acting as an entry point
to the broader processing workflow.
For more advanced, compute-intensive workloads—especially those involving AI or ML
inference—container-based processing is highly effective. Amazon Elastic Kubernetes
Service (EKS) provides a robust and scalable platform to orchestrate containers that
execute various stages of the image processing pipeline. For instance, different
microservices can be deployed to handle preprocessing, inference with deep learning
models, and result aggregation or logging. EKS supports auto-scaling and offers high
fault tolerance, making it well-suited for dynamic and demanding environments.
AI-based analysis can be further enhanced by integrating Amazon Rekognition, a
powerful image and video analysis service. Rekognition delivers real-time insights
through object detection, facial analysis, and content moderation capabilities—
eliminating the need to build and train custom ML models from scratch.
Security remains a top priority in this architecture. Fine-grained access controls are
enforced through AWS Identity and Access Management (IAM), following the principle of
least privilege to ensure secure access between services. All data is encrypted both in
transit and at rest, and system behavior is continuously monitored using Amazon
CloudWatch to detect performance issues or anomalous activity.
By leveraging these AWS services effectively, a Cloud Engineer can deliver an image
processing solution that is not only powerful and cost-efficient but also highly adaptable
to evolving business needs, increasing traffic loads, and future enhancements.

- DynamoDB
As part of the data management strategy, the user is required to provision an
Amazon DynamoDB table named Tokens, which will serve as a high-performance,
scalable NoSQL database for securely storing token-related data. The table must
be configured with a partition key named token of type String, which uniquely

identifies each item in the table. This table will be the central source of truth for
managing authentication or session tokens in real-time applications.
To support real-time processing and auditing of token data, the DynamoDB table
must be integrated with Amazon Kinesis Data Stream. This configuration allows
DynamoDB Streams to capture data modification events (INSERT, MODIFY,
REMOVE) and send them to a Kinesis Data Stream. With this setup, every change
to the Tokens table will be streamed out in near real-time, enabling downstream
services such as analytics engines, event processors, or machine learning
pipelines to consume and act upon the data immediately.
Activating DynamoDB Streams with Kinesis ensures the infrastructure adheres
to modern best practices for event-driven architecture, allowing for loosely
coupled systems and scalable real-time processing. This setup is particularly
powerful in scenarios requiring traceability, anomaly detection, or monitoring
access patterns across distributed systems.
- Kinesis DataStream
To support real-time data ingestion and event-driven processing, the user is
required to provision an Amazon Kinesis Data Stream named techno-kinesisyourname using Terraform. This stream will act as the central pipeline for
collecting and distributing time-sensitive data from various sources, such as
application logs, DynamoDB stream events, or IoT devices, enabling scalable and
responsive architectures.
The stream must be configured with Provisioned capacity mode, which allows for
fine-grained control over performance and cost. Under this mode, the user must
provision 1 shard, which provides a baseline throughput of 1 MB/sec for write and
2 MB/sec for read operations — sufficient for moderate to high-volume real-time
data use cases. If higher throughput is needed in the future, additional shards can
be added dynamically.
In alignment with data lifecycle best practices and compliance considerations, the
data retention period should be explicitly set to 1 day (24 hours). This
configuration ensures that streamed data is available for replay and recovery within

a limited window, helping to reduce storage costs and minimize potential data lag
while preserving the ability to react to transient failures or processing delays.
